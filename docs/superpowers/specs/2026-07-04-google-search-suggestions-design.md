# Google 实时搜索建议设计

> 日期：2026-07-04 | 状态：设计完成

## 概述

为 ziqi-tab 的搜索框增加实时搜索建议。无论当前选中了哪个搜索引擎，建议词统一来自 Google 建议源；用户选择建议后，最终搜索仍通过当前选中的搜索引擎跳转。

本次设计坚持最小改动：不新增 background/service worker，不拆新模块，在现有搜索栏结构和 `search.js` 内补齐“输入 -> 请求建议 -> 渲染列表 -> 选择建议 -> 搜索”的链路。

## 目标

1. 用户输入非空查询时，搜索框下方展示最多 6 条实时建议。
2. 建议词来源固定为 Google，与当前选中的搜索引擎解耦。
3. 用户选择建议后，最终搜索仍走当前搜索引擎。
4. 键盘和鼠标都能高效选择建议。
5. 请求失败时不影响普通搜索。

## 非目标

- 不支持按不同搜索引擎切换不同建议源。
- 不支持自定义建议源配置。
- 不新增错误提示、加载骨架、最近搜索历史。
- 不重构现有搜索引擎切换架构。

## 交互设计

### 展示规则

- 当输入框内容为非空白文本时，触发建议请求。
- 建议列表显示在搜索框下方，最多展示 6 条。
- 当输入为空、仅空白、请求失败、或无建议结果时，隐藏建议列表。
- 建议列表默认不预选任何项，只有在用户使用键盘遍历后才出现高亮项。

### 输入与防抖

- 输入框 `input` 事件触发建议查询。
- 请求前使用 `200ms` 防抖，避免每次按键都直接发请求。
- 使用“最近请求优先”规则：如果较早请求比新请求更晚返回，旧结果必须被丢弃，不得覆盖当前列表。

### 键盘交互

- `ArrowDown`：高亮下一条建议。
- `ArrowUp`：高亮上一条建议。
- `Tab`：当建议列表打开时，高亮下一条建议。
- `Shift+Tab`：当建议列表打开时，高亮上一条建议。
- `Enter`：
  - 若当前有高亮建议，采用该建议并立即搜索。
  - 若当前没有高亮建议，按输入框原始内容搜索。
- `Escape`：关闭建议列表。

### 与现有引擎切换的关系

- 当建议列表打开时：
  - `Tab` / `Shift+Tab` 优先用于遍历建议。
  - 不触发现有“循环切换搜索引擎”逻辑。
- 当建议列表关闭时：
  - 保持现有行为不变。
  - `Tab` / `Shift+Tab` 继续用于循环切换搜索引擎。

### 鼠标交互

- 点击某条建议后：
  - 将建议文本填入输入框。
  - 关闭建议列表。
  - 使用当前搜索引擎立即执行搜索。

## 数据流设计

### 请求来源

- 统一请求 Google 建议接口。
- 建议源仅用于返回建议文本，不影响最终搜索跳转引擎。
- 由于扩展页需要跨域请求，需要在 `manifest.json` 中增加对应 `host_permissions`。

### 前端处理链路

1. 用户在搜索框输入文本。
2. `search.js` 内部的建议逻辑对输入做 trim 判断。
3. 若为空白，则取消待发请求并隐藏列表。
4. 若为非空白，则启动 200ms 防抖。
5. 防抖完成后发起建议请求。
6. 响应返回后校验是否仍为最新请求。
7. 若是最新请求，则渲染建议列表并重置高亮索引。
8. 用户通过键盘或鼠标选中建议。
9. 选中后走现有 `search(query)`，由当前引擎决定跳转 URL。

### 状态管理

建议功能在 `search.js` 中新增以下轻量状态：

- `suggestionItems`：当前建议文本数组。
- `highlightedSuggestionIndex`：当前高亮项索引，默认 `-1`。
- `suggestionRequestSeq`：递增请求序号，用于丢弃过期结果。
- `suggestionDebounceTimer`：输入防抖计时器。

不引入新的全局存储，也不持久化建议结果。

## DOM 与样式设计

### HTML

在搜索框区域新增一个建议列表容器，位置紧邻输入框，保持在搜索栏组件内部，便于定位与样式复用。

新增元素职责：

- 建议容器：控制显示/隐藏。
- 建议列表：承载建议项。
- 建议项：支持 hover、选中高亮、点击搜索。

### CSS

在 `css/search.css` 中新增建议面板样式，视觉上与现有搜索框、引擎菜单保持一致：

- 浮层式下拉面板
- 轻微阴影和圆角
- hover 背景反馈
- 键盘高亮态
- 隐藏态样式

不改动现有引擎菜单的视觉语言，只新增建议列表所需样式。

## 测试策略

本次实现遵循测试先行，先补失败用例，再写生产代码。

### 新增测试场景

1. 输入非空文本后渲染建议列表。
2. 空输入或纯空白输入时隐藏建议列表。
3. 请求失败时不显示建议，但普通搜索仍可用。
4. 仅采用最新请求结果，旧请求不会覆盖新列表。
5. `ArrowDown` / `ArrowUp` 可遍历建议。
6. 建议列表打开时，`Tab` / `Shift+Tab` 遍历建议而不是切换引擎。
7. 建议列表关闭时，`Tab` / `Shift+Tab` 仍切换引擎。
8. 有高亮建议时按 `Enter` 会采用该建议并搜索。
9. 无高亮建议时按 `Enter` 按输入原文搜索。
10. 点击建议项会采用建议并按当前引擎搜索。
11. 选择建议后，最终跳转 URL 仍取决于当前选中的引擎，而不是 Google。
12. `Escape` 会关闭建议列表。

### 测试方法

- 在 `tests/search.test.js` 中 mock `fetch`。
- 不依赖真实网络，也不验证 Google 接口本身。
- 关注本地行为：请求时机、列表渲染、键盘规则、最终跳转。

## 风险与约束

### 跨域权限

- 扩展页发起 Google 建议请求需要 `host_permissions`。
- 如果权限配置不完整，功能会表现为始终无建议，因此测试需要覆盖失败分支，但产品行为保持静默降级。

### Tab 键冲突

- 当前项目已使用 `Tab` / `Shift+Tab` 切换搜索引擎。
- 本次通过“列表打开时建议优先、列表关闭时引擎优先”来解决冲突。
- 这是本次功能最重要的行为边界，必须通过测试锁定。

### UI 一致性

- 建议列表与引擎下拉都属于搜索框相关浮层，样式需要保持协调。
- 但两者职责不同，不合并为同一个面板，也不共享键盘状态。

## 成功标准

1. 输入非空文本时，能稳定显示 Google 建议词。
2. 用户可以用鼠标、方向键、Tab 键选择建议。
3. 选择建议后，最终搜索仍走当前引擎。
4. 建议请求失败时，不影响原有搜索功能。
5. 新增测试先失败后通过，且现有搜索测试无回归。
